# 1분체크 v2 "심플" 계획 (2026-10-08)

브랜치 `simple-v2`. 기존 `main`과 GitHub Pages 사이트는 그대로 두고, 이 브랜치만 Vercel로 배포한다.
되돌리기: `git checkout main` (단계마다 따로 커밋했으므로 단계별 되돌리기도 가능).

## 왜 바꾸나 (사용자 입장 진단)
- 결과 화면이 모바일 기준 약 9화면(7,000px). 한 항목에 숫자가 3개(현재 가능성 %, 100명 중 몇 명, 또래의 몇 배)이고,
  그 아래 N년 발생 위험·설문 점수·검진 기준·추가 체크 7개가 서로 다른 방식으로 이어진다. "그래서 나 괜찮아?"를 사용자가 스스로 조립해야 한다.
- 영상의 클라이맥스("줄이면?")가 앱에서는 '자세히 보기' 안이나 탭 뒤에 숨어 있다.
- 바꿔보기가 '현재 가능성'(지금 검사하면 기준에 해당할 확률)을 바꿔 보여줘서 "4kg 빼면 '이미 당뇨일 확률'이 줄어요"라는 어색한 말이 된다.
- 지금 상태를 '기준선까지의 거리'로 보여주지 않는다.

## 핵심 사용 장면
TV·유튜브·단톡방에서 링크를 눌러 가볍게 1분 → 그다음 건강검진 결과지 숫자를 아주 쉽게 풀어서 이야기해 준다(짧은 모션).

## 결정 사항
| 항목 | 결정 |
|---|---|
| 변화 표시 | **기준선 방식.** BMI 23·25·30, 허리 여 85·남 90cm 선을 넘나드는지로 보여준다. 미래 위험은 계산식 기간 그대로("10년 안에", "4년 안에"). 5년으로 늘리거나 줄이지 않는다 |
| 미래 위험 근거 | 10년 당뇨(Oh 2021 KDR, 40–69세, 허리 필수, 몸무게는 계산에 없음, 허리 기준선에서만 바뀜). 4년 고혈압(Lim 2013, 검진 혈압 필요, BMI 25·30에서 바뀜). 점수표가 단조롭지 않아 선을 넘어도 % 가 그대로·오르면 점수 변화만 보여준다 |
| 또래 비교 | 결과 화면에는 그림 하나: 같은 성별·나이 100명을 위험이 낮은 순서로 세웠을 때 내 위치(백분위 표 있는 항목) + 한 단어(낮은 편·비슷·높은 편). '몇 배'와 링 그래프는 결과 첫 화면에서 뺀다 |
| 분야 | 수면·마음·소화·식생활은 **숨김**(코드는 그대로, `web/src/lib/features.ts` 스위치) |
| 검진 풀이 입력 | 지금은 숫자 직접 입력. 나중에 결과지 사진 → Claude Haiku로 읽어 칸을 채우고 사용자가 확인 |
| 서버 | Vercel(호스팅·공유 미리보기·익명 방문 수). Supabase는 로그인·기기 간 동기화가 필요해질 때 다시 검토 |
| 엔진 | 계산식·수치는 바꾸지 않는다. 화면에서 쓰려고 기존 계산을 그대로 꺼내는 export만 추가할 수 있다 |
| 문구 | 급한 안내는 '지금 바로 병원 가세요'만 쓴다 |

## 단계
### 0단계: 정리
- `features.ts`로 수면·마음·소화·식생활 끄기 → 분야 고르기 화면 없이 생활 다음 바로 결과. 숨긴 분야의 상세 주소는 결과로.
- 시작·소개 화면을 건너뛰고 바로 기본정보(2단계 입력).

### 1단계: 결과 3장
1. **지금 내 상태**: 기존 판정(verdict) 그대로, 한 줄 + 할 일 하나(급한 안내·병원 확인은 기존처럼 모두).
2. **또래 100명 중 나**: 당뇨·고혈압·지방간 탭, 100개 점 그림, 한 단어, 정확한 %는 누르면.
3. **이대로면 vs 바꾸면**: 결과 화면 안 몸무게·허리 슬라이더, 기준선 막대 위 점 이동, 선을 넘을 때 10년 당뇨·4년 고혈압 전후, "기준선까지" 빠른 버튼.
- 나머지(설문 점수, 추가 체크, N년 표, 근거, 읽는 법, 현재 가능성 목록)는 "모든 항목 보기"(`#/all`)로.
- 새 함수 `lib/lines.ts`(기준선 거리·전후 계산) + 단위 테스트.

### 2단계: 검진결과 쉽게 풀기
- 입구: 랜딩 "검진 결과지 받으셨나요?", 결과 화면 아래. 성별·나이만 있으면 시작.
- 숫자 하나당 카드: 정상·주의·높음 구간 막대에 점이 미끄러져 들어가는 모션(모션 줄이기 설정이면 정지), 한 줄 뜻, 할 일 하나.
- 구간 기준은 `lib/labZones.ts`에 근거와 함께 모으고 테스트.

### 3단계: 랜딩을 영상 흐름으로
- 첫 화면에서 바로 숫자 4개 맛보기 → 100명 점 그림 → "줄이면?" → 검진 풀이 입구 → 짧은 FAQ.
- 분야 칩·긴 근거 섹션 정리. 영상은 누르면 재생(처음 로딩 가볍게).

### 4단계: Vercel·공유
- 저장소 루트 `vercel.json`(설치·빌드는 `web/`, 결과물 `web/dist`). Vercel 빌드에서는 주소 기준 경로 `/`, GitHub Pages는 `/1mincheck/`.
- 공유 미리보기 이미지(개인 숫자 없음), 빌드 때 Vercel 주소 자동 반영.
- 쿠키 없는 익명 방문 통계(Vercel Web Analytics)를 Vercel 빌드에서만 켬. 문구: "입력한 건강정보는 보내지 않아요 · 방문 수만 익명으로 세요".
- "친구도 해보라고 보내기" 버튼.

### 나중
- 결과지 사진 읽기: Vercel 서버 함수 → Claude API(Haiku). 키는 서버에만. 보내기 전 동의, 저장 안 함, 읽은 숫자는 칸에만 채우고 사용자가 확인 후 반영, 횟수 제한.
- Supabase: 로그인·기기 간 기록 동기화가 필요해질 때. 건강정보는 민감정보라 별도 동의·처리방침 필수.
- 홍보영상: 앱 확정 뒤 같은 화면 기준으로 다시 제작(현재 영상은 지방간 숫자가 장면마다 5.9%/6.4%로 다름).
- 수익(이용료 없음): 기업·지자체 화이트라벨, 측정 도구 제휴, 콘텐츠·광고, 공익 캠페인 후원. 상업화 전에 식약처 사전상담과 설문 라이선스(ISI·STOP-Bang·GerdQ) 확인.

## 검증
- `web`: `npm test`(기존 + 새 함수 테스트), `npm run build`. `engine`: 엔진 테스트.
- 실제 브라우저 흐름 테스트 `web/scripts/e2e-v2.mjs`, 모바일 360·430px 캡처.
- 결과 화면 목표: 모바일 기준 화면 3장 이내.

## 직접 해야 하는 일 (사용자)
1. vercel.com에 GitHub로 로그인 → 1mincheck 저장소 가져오기 → 브랜치 `simple-v2`로 배포(루트 폴더는 그대로, 설정은 `vercel.json`이 함).
2. (선택) Vercel 프로젝트의 Analytics 탭에서 Web Analytics 켜기.
