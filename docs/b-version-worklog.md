## 2. A와 B 격리

- 출처(origin)가 같다(`fobesseo1.github.io`). 그래서 저장 키를 나눴다: A `1mincheck.draft`·`1mincheck.records`·`1mincheck.mini` / B `1mincheck-b.draft`·`1mincheck-b.records`·`1mincheck-b.mini`. B는 A 키를 읽거나 쓰거나 지우지 않는다. B의 ‘기록 지우기’는 B 기록만 지운다(e2e에서 A 키에 표시값을 넣고 끝까지 그대로인지 확인).
- 서비스 워커: A의 `sw.js`는 활성화될 때 자기 것이 아닌 캐시를 모두 지운다. B를 그대로 복사하면 B가 A의 오프라인 캐시(`1mincheck-v1`)를 지우게 되므로, B는 캐시 이름을 `1mincheck-b-v1`로 바꾸고 `1mincheck-b-`로 시작하는 캐시만 정리한다. 범위(scope)도 `/1mincheck-b/`라 A 페이지 요청을 가로채지 않는다. (반대로 A의 서비스 워커는 B 캐시를 지울 수 있다 — A 코드를 바꾸지 않기로 해서 그대로 두었고, B는 캐시가 지워져도 네트워크에서 다시 받는다.)
- 기본 주소 `/1mincheck-b/`, 제목·앱 이름에 ‘비교용 B’, 검색 제외(`noindex`).

## 4. 바꾼 것 (B에서만)

새로 만든 표시 함수: `web/src/lib/b.ts`(테스트 `b.test.ts`), 프로필 `web/src/lib/bProfiles.ts`.

- **홈페이지**: 제목 유지. 설명 ‘간단한 몸 정보와 생활습관으로, 지금 건강을 가늠해 보세요.’ 시작 버튼 옆 ‘기본 체크 약 1분 · 추가 질문은 선택 · 만 19세 이상’, 검진값 안내 문구. 첫 화면 오른쪽(휴대폰은 설명·버튼 아래)에 **대표 결과 예시**: 가상의 42세 남성을 현재 엔진으로 계산한 값(‘예시 · 내 결과가 아니에요’ 표시). 순서 = 핵심·예시 → 미니 체험 → 건강 분야 → 결과 읽는 법(새 섹션) → 통계와 연구 → 정보 보호·FAQ → 마지막 시작. 반복되던 ‘이용 방법’·‘이렇게 보여드려요’ 섹션은 ‘결과 읽는 법’으로 합쳤다. 20초 자동 재생 영상은 첫 화면에서 빼고, 45초 영상은 버튼으로 유지.
- **미니 체험**: 같은 체형 비율을 ‘100명 중 약 ○명 · 또래 평균 ○%보다 높아요(약 ○배)’로. 값·결론 단계는 그대로.
- **결과**: ① 상태 안내(기존 판정; 긴급은 할 일까지 맨 위) → ② 주요 결과(이름 → 현재 가능성 추정 % → 비슷한 조건의 100명/1,000명 중 약 ○명 → 또래 평균 비교 → 필요하면 확인 안내, ‘왜 이렇게 나왔나요?’ 접기) + 체형 + 설문 결과·아직 체크하지 않은 분야 → ③ 이번 결과에 반영한 정보(몸 정보·생활·진단·반영한 검진값·나머지는 추정) → ④ 지금 할 일(기존 할 일 그대로, 잘하고 있는 점) → ⑤ 저장·진료용 요약·알려주기 → ⑥ 자세히 보기(또래 배수, 바꿔보기 요약, **앞으로 N년 안의 발생 위험을 따로 묶음**, 생활·검진 체크, 설문 점수, 읽는 법).
- **④ 칭찬 문구**: 실제 답한 좋은 습관만(비흡연·금연·운동·금주·정상 체중/허리), 검진값은 넣은 것 중 정상인 것만 이름으로. 검진값이 없으면 검진 얘기를 하지 않는다. 판정 단계·할 일은 그대로.
- **상세**: 숫자 순서를 현재 가능성 추정 → 100명(1,000명) 중 → 또래 평균 문장으로. 큰 ‘또래의 ○배’ 제목은 문장 뒤 괄호로.
- **기록**: ‘지난번과 비교해 달라진 결과’ + ‘입력한 몸 정보와 답변이 바뀌면서 추정 결과가 다시 계산됐어요’, 같은 입력이면 ‘결과도 같아요’. ‘좋아진 항목’ → ‘추정이 낮아진 항목’. 입력한 검진 수치 변화를 추정과 따로 표시.
- **바꿔보기**: 안내 문장과 ‘가상의 입력 변화에 따른 계산이에요. 실제 치료 효과나 질병 감소를 보장하지 않아요’.
- **검진 수치**: 없어도 된다는 안내, 넣은 값이 쓰이는 항목, 입력 당시 값으로 다룬다는 설명.
- **디자인**: 기본 자간 −0.5%, 한국어 단어 단위 줄바꿈 유지, 결과의 큰 배수·짙은 카드 줄임.

## 6. 문서와 코드 대조

- 공유: 코드상 서비스 소개 문구 + 앱 주소만 공유(개인 결과 아님) — 조사 문서와 같음.
- 진료용 인쇄: A는 기록 화면에서만, 기록 2개 이상일 때만 보이는 `window.print()`(기록 비교 화면을 인쇄) — 첫 결과만으로는 쓸 수 없었다. B에서 새로 해결.
- 홈페이지: A에 영상·미니 체험·결과 예시가 이미 있음 — B는 이를 유지·재배치.
- 지방간: 40세 미만 여성은 폐경 질문을 하지 않는데 엔진이 폐경을 ‘모름’으로 두고 범위를 계산한다(P1 ‘1–1%’, P13 ‘11–21%’). 계산은 그대로 두고 B 표시만: 양끝이 같으면 ‘약 1%’, 범위 이유는 실제로 비어 있는 답만(‘폐경 여부(40세 미만은 묻지 않음)’).

## 7. 표현상 충돌·제한 (판정은 바꾸지 않음)

1. **작은 절대값·큰 또래 배수(P13)**: 당뇨 0.6% 대 또래 0.3%(약 2.0배)로 기존 판정은 ② 병원 확인(‘혈당 확인이 필요해요’). B 결과 줄은 ‘또래 평균 0.3%보다 높지만(약 2.0배), 추정 가능성 자체는 낮은 편이에요’라고 함께 말하고, 1% 미만이면 숫자를 빨간색으로 강조하지 않는다. 위의 상태 카드는 빨간 병원 확인 그대로라 **한 화면에 ‘확인 필요’와 ‘낮은 편’이 같이 나온다.** 배수만으로 병원 확인을 권하는 기준은 별도 검토 사항.
2. **1–10% 구간**은 ‘낮은 편’이라 하지 않고 ‘또래 평균 ○%보다 높아요(약 ○배)’ + ‘100명 중 약 ○명’만 쓴다(경각심을 줄이지 않기 위해).
3. 또래 배수 표기는 소수 한 자리 반올림이라 1.96배가 ‘약 2.0배’로 보이지만 단계는 ‘2배 미만’ 기준으로 판정된다(A와 같음).
4. 영상(20초·45초)은 A 화면 기준으로 만든 것이라 B의 숫자 표현과 다르다. B에서는 버튼으로만 연다.
5. 긴급(①)은 혈압 180/120 이상을 혈당 300 이상보다 먼저 보여주는 기존 순서를 그대로 둔다(P8).
6. 사용성은 자동 테스트로 입증되지 않는다. 실제 비교 응답으로 판단한다.
